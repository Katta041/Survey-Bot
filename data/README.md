# Data folder

All data committed under `data/` is synthetic. It was generated by
`scripts/generate_synthetic_data.py` from a fixed random seed and contains no
real survey responses, recordings, names, phone numbers, addresses or other
personal data.

| Path | Contents |
| --- | --- |
| `production/tn_survey_sanitized.csv` | 240 fictional survey rows (`SYN-0001` to `SYN-0240`) with the columns the chatbot expects: `sample_id`, `url`, `transcript`, `qc_status`, `qc_score`, `qc_comment`, `MLA_Satisfaction`, `Desires_Change`, `Next_CM`, `Vote_2026`, `Caste`, `Age_Group`, `Gender`, `Occupation`. Transcripts are short Tamil and English snippets written for this demo. The answer distributions are random and say nothing about real public opinion. |
| `audio_samples/*.wav` | Three tiny generated WAV files (sine tones and silence, 16 kHz mono) for smoke-testing the audio pipeline. They contain no speech, so transcription returns little or nothing. Use your own recordings for real tests. |
| `db/telemetry.db` | SQLite telemetry store seeded with fictional LLM and Sarvam events so the observability dashboard has something to show. |

The `url` column points at `example.com` placeholders; no audio exists at
those addresses.

To regenerate everything:

```bash
python scripts/generate_synthetic_data.py
```

The dashboard's default view covers the last 30 days. To refresh only the
telemetry dates, run `python scripts/generate_synthetic_data.py --telemetry-only`.

Real survey exports and recordings must never be committed. Keep them under
`data/raw/` and `data/audio_samples/` locally; `.gitignore` excludes
everything in `data/` except the synthetic files listed above.
